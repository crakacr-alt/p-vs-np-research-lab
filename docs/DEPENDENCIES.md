# Зависимости

## Core

Основная лаборатория v1.0 использует только стандартную библиотеку Python.

Почему: текущие алгоритмы достаточно просты, и лишняя зависимость затруднила бы понимание без научной выгоды.

Это **не ограничение проекта**. Можно использовать любые библиотеки, если они полезны.

## `mcp`

Установка:

```bash
pip install -e ".[mcp]"
```

Версия: `mcp>=2,<3`.

Зачем: даёт стандартный Model Context Protocol, чтобы AI-клиент мог запускать инструменты лаборатории. В 1.0 используется актуальный high-level класс `MCPServer` из SDK 2.x.

Где: `pnp_lab/mcp_server.py`.

Без неё: весь SAT-код и CLI работают полностью.

## `python-sat`

Установка:

```bash
pip install -e ".[reference]"
```

Зачем: это независимая реализация SAT solver-ов. Нужна как контрольный reference, чтобы не доверять только нашему коду.

Где: `pnp_lab/reference_solver.py`.

Без неё: наши solver-ы работают; просто нет внешней независимой сверки.

## `ruff`

Установка:

```bash
pip install -e ".[dev]"
```

Зачем: быстро находит часть ошибок и проблем стиля.

Где: CI и локальная разработка.

Без неё: программа работает, но проверка качества кода слабее.

## Будущие зависимости

Допустимы, например:

- NumPy/SciPy — если понадобится эффективная линейная алгебра;
- NetworkX — если графовый анализ станет достаточно сложным;
- matplotlib/pandas — если появится отдельный слой анализа результатов;
- Z3 — для сравнительных SMT-экспериментов;
- специализированные BDD-библиотеки;
- SAT proof checkers.

Правило одно: каждая зависимость должна решать конкретную проблему, а не добавляться «для солидности».


## `build` и `twine`

Установка:

```bash
pip install -e ".[release]"
```

Зачем:

- `build` собирает стандартные Python-артефакты `wheel` и `sdist`;
- `twine check` проверяет metadata и README внутри собранного пакета.

Где: release-проверка GitHub Actions.

Без них: запуск лаборатории не меняется. Они нужны только для проверки, что
версия проекта действительно может распространяться как корректный Python-пакет.
