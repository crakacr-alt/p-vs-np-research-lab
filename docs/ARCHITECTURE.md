# Архитектура проекта

## Почему архитектура пока маленькая

Первая версия специально не использует десятки классов и сложные паттерны проектирования.

В v0.1 внешние фреймворки пока не нужны, потому что базовый DPLL, парсер DIMACS и тесты можно сделать средствами стандартной библиотеки Python.

Это не запрет на сторонние зависимости. Если в следующих версиях библиотека заметно упростит реализацию, ускорит эксперименты или даст надёжный научный инструмент, её можно подключить. При этом в документации обязательно объясняется, **зачем она нужна и почему выбрана именно она**.

Цель архитектуры — чтобы любой модуль можно было читать сверху вниз и понимать, какую задачу он решает.

## Слои

### 1. `cnf.py`

Отвечает только за данные:

- хранит CNF-задачу;
- читает DIMACS;
- проверяет найденную модель.

Он не решает SAT.

### 2. `dpll.py`

Содержит первый точный алгоритм.

DPLL выбран как **baseline** — контрольный алгоритм, с которым мы будем сравнивать будущие методы.

Основные действия:

```text
формула
   |
   v
подстановка уже известных значений
   |
   +---- противоречие ---> назад
   |
   +---- все клаузы выполнены ---> SAT
   |
   v
unit propagation
   |
   v
выбор переменной
   |
   +---- True
   |
   +---- False
```

### 3. `generator.py`

Создаёт случайные 3-SAT задачи.

Нужен не для доказательства, а для воспроизводимых экспериментов.

### 4. `experiment.py`

Берёт задачи разного размера и записывает:

- число переменных;
- число клауз;
- число ветвлений;
- число рекурсивных вызовов;
- время.

Так мы видим, где алгоритм начинает резко усложняться.

### 5. `counterexample.py`

Пока это простой стресс-тестер.

Он перебирает разные случайные seeds и ищет формулу, на которой DPLL сделал больше всего ветвлений.

Важное различие:

**трудный тест ≠ математический контрпример гипотезе.**

### 6. `cli.py`

Это командная строка.

Она соединяет остальные части, но сама не содержит математики SAT.

## Почему это полезно для исследования P vs NP

Наша дальнейшая идея — добавлять разные точные способы представления одной и той же задачи.

Например:

```text
                  SAT
                   |
        +----------+----------+
        |          |          |
       DPLL       XOR       Graph
        |          |          |
        +----------+----------+
                   |
             точная проверка
```

Потом можно исследовать **representation switching** — переключение между представлениями, когда одно из них начинает сильно разрастаться.

Но это появится только после того, как базовая версия будет хорошо протестирована.
