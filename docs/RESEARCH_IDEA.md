# Исследовательская гипотеза

## Исходная идея

Одна и та же логическая задача может быть удобной или неудобной в зависимости от способа представления.

Пример: структура, похожая на XOR, может быть неудобна обычному ветвящемуся поиску, но естественна для линейной алгебры над GF(2).

Отсюда рабочая гипотеза:

> во время точного решения полезно не только выбирать следующую переменную, но и менять математическое представление остаточной задачи.

## Polynomial Representation Switching

Сильная версия гипотезы выглядела бы так:

> Для любой 3-CNF размера N существует эффективно находимая последовательность точных представлений и переходов между ними, в которой каждый промежуточный объект имеет размер \`poly(N)\`, а суммарная работа также \`poly(N)\`.

Если бы это удалось доказать конструктивно, это могло бы привести к полиномиальному алгоритму для 3-SAT и, следовательно, к \`P = NP\`.

Но именно эта универсальная граница сейчас **не доказана**.

## Что проверяет текущий код

v0.2 не реализует полный representation switching. Он строит первый научный стенд:

- baseline;
- точные упрощения;
- decomposition;
- memoization;
- измерение сложности;
- генерация трудных случаев;
- журнал гипотез;
- воспроизводимые эксперименты.

Это инфраструктура для попытки опровергать и уточнять гипотезу.

## Почему нужен adversarial search

Если новый метод работает на случайных задачах, это слабое свидетельство.

Поэтому лаборатория должна активно искать входы, на которых метод ломается.

Правильная последовательность:

\`\`\`text
гипотеза
-> реализация
-> обычные тесты
-> adversarial tests
-> найденное слабое место
-> новая гипотеза
\`\`\`

## Что будет следующим научным шагом

1. добавить структурные семейства benchmark-задач;
2. добавить точный XOR-модуль;
3. добавить внешний CDCL solver как reference;
4. измерить, когда decomposition/memoization реально меняют форму роста;
5. построить первый протокол representation switching;
6. искать семейства, на которых все доступные представления одновременно разрастаются.
