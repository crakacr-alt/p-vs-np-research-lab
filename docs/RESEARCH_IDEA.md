# Исследовательская идея

## Что мы пытаемся проверить

Для NP-полной задачи 3-SAT простой полный перебор в худшем случае может рассматривать огромное число вариантов.

Исходная гипотеза проекта:

> возможно, разные части одной задачи удобно представлять разными точными способами, а своевременное переключение между ними позволит сильно сжимать пространство поиска.

Рабочее название:

**Polynomial Representation Switching**

По-русски:

**полиномиальное переключение представлений**.

## Почему это пока не решение P = NP

Чтобы действительно получить P = NP, недостаточно показать, что программа быстро решила миллион тестов.

Нужно доказать, что для **любой** входной 3-SAT задачи время ограничено полиномом, например:

```text
T(n) <= C * n^k
```

где k — фиксированная константа.

Такого доказательства у проекта нет.

## Что можно проверить экспериментально

Мы можем честно исследовать более узкие вопросы:

1. На каких семействах обычный DPLL резко замедляется?
2. Можно ли распознать структуру этих задач?
3. Помогает ли другое точное представление?
4. Можно ли объединить много состояний в один эквивалентный класс?
5. Существует ли семейство, которое одновременно плохо для всех наших методов?

## Будущие представления

Планируется постепенно изучать:

- CDCL — современное развитие SAT-поиска;
- XOR и Gaussian elimination;
- графовые разбиения;
- BDD — Binary Decision Diagrams;
- алгебраические представления;
- memoization;
- canonicalization;
- symmetry reduction.

## Роль ИИ в будущем

ИИ не должен говорить: «P = NP доказано».

Допустимая роль:

```text
состояние задачи
      |
      v
ИИ предлагает следующий метод
      |
      v
обычная программа проверяет результат
```

То есть ИИ может быть исследовательской эвристикой, но не источником математической истины.

## Критерий успеха

Даже если проект никогда не решит P vs NP, полезным результатом будет:

- понятный экспериментальный SAT-стенд;
- набор трудных воспроизводимых примеров;
- сравнение точных методов;
- наблюдения о том, где каждый метод ломается;
- новые проверяемые гипотезы.

Если когда-либо появится кандидат на полиномиальный алгоритм, следующая задача — не объявить победу, а максимально агрессивно искать контрпример и формальное доказательство границы.
