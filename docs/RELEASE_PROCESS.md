# Как выпускать новую версию

Версия проекта хранится в нескольких местах, поэтому перед релизом их нужно
синхронизировать.

1. Выбрать SemVer-номер.
2. Обновить:
   - `pyproject.toml`;
   - `pnp_lab/__init__.py`;
   - README;
   - `CITATION.cff`.
3. Записать изменения в `CHANGELOG.md`.
4. Добавить `docs/RELEASE_<version>.md`.
5. Пройти [release checklist](RELEASE_CHECKLIST.md).
6. Открыть отдельный PR.
7. Дождаться зелёных tests и CodeQL.
8. Слить PR в `main`.
9. Проверить post-merge CI.
10. Только потом создать tag `vX.Y.Z`.

После tag workflow ещё раз запускает correctness/style checks, собирает wheel и
sdist, проверяет их через twine и создаёт GitHub Release.

Если solver дал новый интересный результат, это само по себе не повод повышать
версию как «доказательство». Версия описывает состояние программы, а не статус
математической гипотезы.
