# Что проект даёт на практике

## 1. Проверка идеи «сменить язык задачи»

До 1.0 проект в основном измерял обычный SAT-поиск.

В 1.0 появляется реальный эксперимент:

```text
одна и та же логическая информация
        |
        +--> CNF: набор клауз
        |
        +--> XOR: система линейных уравнений над GF(2)
```

Для XOR-структуры линейная алгебра может быть естественнее поиска по дереву.

Лаборатория автоматически распознаёт точную 3-CNF-кодировку XOR и передаёт её
другому решателю.

Это первый рабочий пример той самой концепции, вокруг которой строится проект.

## 2. Можно измерять не только секунды

Секунды плохо сравнивать между разными компьютерами.

Поэтому проект считает:

- decisions;
- recursive calls;
- unit propagations;
- cache hits;
- decompositions;
- XOR equations detected;
- XOR propagations;
- direct XOR solves;
- representation switches.

Это позволяет понять **почему** метод стал быстрее или медленнее.

## 3. Можно ломать собственные идеи

Команда:

```bash
pnp-lab hunt --variables 30 --clauses 126 --iterations 1000
```

не пытается подтвердить гипотезу. Она ищет формулу, которая заставляет текущий
solver ветвиться сильнее.

Для научного проекта это полезнее, чем собирать только удачные примеры.

## 4. Можно безопаснее менять алгоритм

После нового правила можно запустить:

```bash
pnp-lab verify --variables 8 --clauses 30 --count 200 --bruteforce
```

и сравнить сложный solver с независимым полным перебором.

При установленном PySAT можно добавить внешний reference.

## 5. Можно дать лабораторию AI-модели

Через MCP модель получает не «право доказать P=NP», а инструменты:

- запустить точное решение;
- запустить benchmark;
- искать hard case;
- вести гипотезы;
- получать метрики.

Так модель превращается из генератора текста в исследовательского помощника,
который обязан опираться на результаты вычислений.

## 6. Можно запускать формальную машину Тьюринга

Версия 1.1 добавляет отдельную эталонную модель вычисления.

```bash
pnp-lab tm examples/turing_even_ones.json 1010 --trace
```

Она полезна не как быстрый solver, а как способ буквально считать шаги
формального вычисления и видеть работу ленты/головки. Это помогает отделять
понятие «алгоритм быстро работает на моём компьютере» от теоретического понятия
числа шагов как функции размера входа.

## Где это может быть полезно кроме P vs NP

Та же инфраструктура подходит для:

- изучения SAT/SMT;
- formal verification;
- model checking;
- тестирования эвристик;
- анализа логических ограничений;
- учебных исследований по вычислительной сложности;
- экспериментальных задач информационной безопасности, где задача сводится к SAT.

## Чего проект пока не даёт

Он не даёт:

- общего polynomial SAT solver;
- доказательства P=NP;
- доказательства P!=NP;
- гарантии, что XOR switch помогает на произвольной формуле;
- промышленной производительности уровня ведущих CDCL solver-ов.

Его текущая практическая ценность — **воспроизводимая лаборатория для проверки
алгоритмических гипотез**.
