# Гайд для студента первого курса

Этот файл нужен, чтобы проект не превращался в «чёрный ящик».

Если ты только начал изучать программирование, дискретную математику и информационную безопасность — это нормально. Для работы с v0.1 не нужно знать сложную теорию вычислительной сложности.

## Что достаточно знать для начала

Полезно понимать всего пять вещей:

1. переменная может быть True или False;
2. операция ИЛИ истинна, если истинен хотя бы один аргумент;
3. операция И истинна, если истинны все части;
4. функция может вызывать саму себя — это рекурсия;
5. словарь Python хранит пары «ключ -> значение».

Этого уже хватает, чтобы читать базовый DPLL solver.

## Что такое SAT простыми словами

SAT спрашивает:

> можно ли подобрать значения True/False так, чтобы логическая формула стала истинной?

Пример:

```text
(x1 ИЛИ x2) И (НЕ x1 ИЛИ x2)
```

Один подходящий ответ:

```text
x1 = False
x2 = True
```

Обе части формулы становятся истинными, значит это SAT.

Если взять:

```text
x1 И НЕ x1
```

никакого значения x1 не хватит. Это UNSAT.

## Что такое CNF

CNF — Conjunctive Normal Form, по-русски конъюнктивная нормальная форма.

Она выглядит как И между группами, внутри которых стоит ИЛИ:

```text
(a ИЛИ b) И (c ИЛИ d) И (НЕ a ИЛИ c)
```

Каждая группа в скобках называется клаузой.

## Как читать DIMACS

Файл:

```text
p cnf 3 2
1 -2 3 0
-1 2 0
```

означает:

- есть 3 переменные;
- есть 2 клаузы;
- положительное число — обычная переменная;
- отрицательное число — отрицание;
- 0 — конец клаузы.

То есть:

```text
(x1 ИЛИ НЕ x2 ИЛИ x3)
И
(НЕ x1 ИЛИ x2)
```

## Как читать код проекта

Лучший порядок:

### Шаг 1. `pnp_lab/cnf.py`

Сначала посмотри:

- `CNFProblem`;
- `parse_dimacs()`;
- `model_satisfies()`.

Этот файл отвечает только за представление задачи и проверку результата.

### Шаг 2. `pnp_lab/dpll.py`

Главная функция:

```python
solve()
```

Она запускает:

```python
_search()
```

А `_search()` делает поиск решения.

Не пытайся сразу запомнить весь алгоритм. Следи только за порядком:

```text
подстановка
-> проверка противоречия
-> unit propagation
-> выбор переменной
-> True
-> False
```

### Шаг 3. `pnp_lab/generator.py`

Это простой генератор случайных 3-SAT задач.

Он полезен для экспериментов.

### Шаг 4. `pnp_lab/experiment.py`

Здесь уже нет нового алгоритма решения.

Файл просто запускает solver на задачах разных размеров и собирает числа.

### Шаг 5. `pnp_lab/counterexample.py`

Этот модуль пытается найти задачу, на которой текущий solver работает хуже.

Это важный исследовательский принцип:

> хорошую гипотезу нужно не только подтверждать, но и пытаться сломать.

## Почему это связано с информационной безопасностью

SAT и похожие методы встречаются рядом с задачами:

- формальной проверки программ;
- анализа логических ограничений;
- проверки корректности протоколов;
- model checking;
- криптоаналитических исследований;
- поиска ошибок в схемах и системах.

Этот проект не является инструментом взлома. Он помогает изучать алгоритмы, логику и вычислительную сложность — фундаментальные темы, полезные в ИБ.

## Что означают основные английские слова

| Термин | Простой смысл |
|---|---|
| SAT | существует подходящее присваивание True/False |
| UNSAT | подходящего присваивания нет |
| solver | программа-решатель |
| clause | клауза, группа литералов через ИЛИ |
| literal | переменная или её отрицание |
| branch | ветвь поиска |
| baseline | контрольный простой вариант для сравнения |
| heuristic | правило, которое помогает выбирать следующий шаг |
| counterexample | контрпример; в наших тестах часто просто особенно трудный случай |
| benchmark | набор задач для сравнения алгоритмов |
| representation | способ представить одну и ту же задачу |

## Что можно менять самостоятельно

Безопасные первые упражнения:

1. поменять порядок `True, False` на `False, True`;
2. изменить правило выбора переменной;
3. добавить ещё один тест;
4. изменить диапазон эксперимента;
5. вывести дополнительные счётчики.

После каждого изменения запускай:

```bash
python -m unittest discover -s tests -v
```

Если тесты проходят — это ещё не гарантирует отсутствие всех ошибок, но уже хороший первый контроль.

## Сторонние библиотеки

Сторонние библиотеки в проекте использовать можно.

Но перед добавлением новой зависимости нужно ответить на простой вопрос:

> какую конкретную проблему она решает?

Например:

- библиотека для графов может понадобиться для анализа структуры SAT-задачи;
- библиотека для численных вычислений может пригодиться для быстрых экспериментов;
- готовый SAT solver можно подключить как контрольный эталон для сравнения;
- библиотека визуализации может понадобиться для графиков роста сложности.

Для каждой новой зависимости в документации нужно объяснить:

- где она используется;
- зачем нужна;
- почему не хватило стандартной библиотеки Python;
- можно ли запустить базовую часть проекта без неё.

## Чего пока не стоит делать

Не нужно сразу добавлять нейросеть, GPU, 20 solver-ов и сложную базу данных только ради сложности.

Сначала важно точно понимать:

- что измеряем;
- почему алгоритм корректен;
- где появляется экспоненциальный рост;
- действительно ли новое улучшение помогает.

И только потом усложнять проект.
