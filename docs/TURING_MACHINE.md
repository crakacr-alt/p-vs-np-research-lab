# Машина Тьюринга

В версии 1.1 в проект добавлена рабочая **детерминированная одно-ленточная
машина Тьюринга**.

## Зачем она здесь

Для SAT-производительности она не нужна: обычный Python-код будет быстрее.

Её роль другая. Машина Тьюринга — формальная модель вычисления, на которой
определяются понятия вычислимости и классов сложности. Поэтому она полезна как
эталонный слой рядом с экспериментальными solver-ами.

Теперь можно отдельно измерять:

- число шагов Turing Machine;
- положение головки;
- использование ленты;
- завершение accept/reject;
- незавершение в пределах заданного step limit;
- точную последовательность состояний через trace.

Это связывает практический код проекта с теоретической постановкой P vs NP.

## Что реализовано

- одна бесконечная в обе стороны лента;
- детерминированные переходы;
- состояния;
- input alphabet и tape alphabet;
- blank symbol;
- движения `L`, `R`, `S`;
- accept/reject states;
- лимит шагов;
- trace;
- JSON-описание машин;
- CLI;
- MCP.

Лента хранится разреженно через Python `dict`: реально хранятся только
непустые клетки. Поэтому головка может уходить в отрицательные индексы.

## Быстрый пример

В репозитории есть:

`examples/turing_even_ones.json`

Машина принимает бинарную строку, если количество единиц чётное.

Запуск:

```bash
pnp-lab tm examples/turing_even_ones.json 1010
```

Ожидаемый результат:

```text
status: ACCEPT
accepted: True
```

Строка с нечётным числом единиц:

```bash
pnp-lab tm examples/turing_even_ones.json 1011
```

даст `REJECT`.

## Trace

```bash
pnp-lab tm examples/turing_even_ones.json 1010 --trace
```

Показываются шаг, state, позиция головки, читаемый символ и окно ленты.

## Формат JSON

```json
{
  "name": "example",
  "states": ["q0", "qa"],
  "input_alphabet": ["1"],
  "tape_alphabet": ["1", "_"],
  "blank": "_",
  "start_state": "q0",
  "accept_states": ["qa"],
  "reject_states": [],
  "transitions": [
    {
      "state": "q0",
      "read": "1",
      "write": "1",
      "move": "R",
      "next": "qa"
    }
  ]
}
```

Для пары `state + read` разрешён только один переход. Если их два, описание
отклоняется как недетерминированное.

## Связь с P vs NP

Машина Тьюринга **сама по себе не приближает доказательство P=NP**.

Польза появляется в другом:

1. алгоритм можно рассматривать как формальное вычисление;
2. можно считать число шагов как функцию размера входа;
3. можно экспериментально сравнивать разные реализации;
4. в будущем можно строить маленькие трансляторы
   `algorithm -> Turing Machine` для учебной проверки оценок сложности.

При этом эксперимент по конечному набору входов всё равно не доказывает
polynomial worst-case.

## Почему сейчас детерминированная, а не nondeterministic

Для первой рабочей версии важнее прозрачность и проверяемость.

Недетерминированную машину разумно добавить отдельно: она требует дерева
конфигураций или другой модели исполнения, и её нельзя путать с обычным
параллельным запуском нескольких потоков.
