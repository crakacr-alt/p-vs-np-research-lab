# P vs NP Research Lab

Учебно-исследовательский проект для экспериментов с задачей **P vs NP** через точное решение SAT-задач, измерение сложности и поиск трудных примеров.

> Важно: этот проект **не является доказательством P = NP**. Его задача — аккуратно проверять идеи, искать слабые места алгоритмов и собирать воспроизводимые результаты.

## Как устроен код проекта

В проекте делается упор на понятность и проверяемость:

- код разбит на небольшие логические файлы;
- сложные места объясняются комментариями на русском;
- сначала используется простой точный алгоритм **DPLL (Davis–Putnam–Logemann–Loveland)**;
- более сложные методы добавляются только тогда, когда понятно, какую проблему они решают;
- сторонние библиотеки **разрешены**, если они действительно полезны для исследования.

### Правило для сторонних библиотек

Если в проект добавляется новая библиотека, в документации должно быть коротко объяснено:

1. **что это за библиотека**;
2. **зачем она нужна**;
3. **почему без неё было бы хуже, сложнее или медленнее**;
4. **какую часть проекта она затрагивает**;
5. **есть ли простой вариант без неё**.

Это нужно, чтобы проект не превращался в набор непонятных зависимостей.

## Зачем это нужно

Главный исследовательский вопрос проекта:

**можно ли уменьшать пространство точного поиска SAT настолько сильно, чтобы рост для всех входов стал полиномиальным?**

Сейчас мы этого не знаем. Поэтому лаборатория делает более скромную, но проверяемую работу:

1. решает SAT-задачи точным алгоритмом;
2. считает количество ветвлений и рекурсивных вызовов;
3. увеличивает размер задач и смотрит, как растёт стоимость решения;
4. автоматически ищет особенно трудные экземпляры;
5. сохраняет основу для будущих методов: разбиения, XOR, BDD, алгебры и переключения представлений.

## Что уже есть в v0.1

- чтение формата **DIMACS CNF**;
- простой точный DPLL solver;
- независимая проверка найденной модели;
- генератор случайных 3-SAT задач;
- эксперимент роста сложности;
- поиск наиболее трудного случайного экземпляра среди набора;
- автоматические тесты.

## Установка

### Вариант 1. Linux / Ubuntu

```bash
git clone https://github.com/crakacr-alt/p-vs-np-research-lab.git
cd p-vs-np-research-lab
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -e .
```

### Вариант 2. Windows PowerShell

```powershell
git clone https://github.com/crakacr-alt/p-vs-np-research-lab.git
cd p-vs-np-research-lab
py -m venv .venv
.venv\Scripts\Activate.ps1
py -m pip install -e .
```

После установки появится команда:

```bash
pnp-lab --help
```

Можно запускать и без установки команды:

```bash
python -m pnp_lab --help
```

## Первый запуск

Решить пример SAT:

```bash
pnp-lab solve examples/simple_sat.cnf
```

Решить пример UNSAT:

```bash
pnp-lab solve examples/simple_unsat.cnf
```

Запустить маленький эксперимент роста:

```bash
pnp-lab experiment --start 10 --stop 30 --step 5
```

Найти наиболее трудный случай среди 100 случайных формул:

```bash
pnp-lab hunt --variables 20 --tries 100
```

## Как работает DPLL

Формула CNF состоит из клауз, соединённых операцией И.

Пример:

```text
(x1 ИЛИ x2) И (НЕ x1 ИЛИ x2)
```

DPLL делает четыре понятных шага:

1. подставляет уже известные значения переменных;
2. если остаётся клауза из одного литерала, значение этой переменной становится вынужденным;
3. если решения ещё нет, выбирает переменную;
4. пробует сначала True, затем False.

Если обе ветви приводят к противоречию — текущая ветвь невозможна.

Это точный алгоритм: если он сообщает SAT, найденную модель дополнительно проверяет отдельная функция.

## Почему это полезно студенту информационной безопасности

Проект помогает на практике потрогать темы, которые потом встречаются рядом с ИБ: булева логика, дискретная математика, рекурсия, алгоритмическая сложность, формальная проверка и constraint solving.

При этом код v0.1 специально не усложняется: сначала важно понимать каждый шаг алгоритма, а уже потом добавлять более мощные методы.

```bash
python -m unittest discover -s tests -v
```

## Что планируется дальше

Следующие версии будут добавляться только после проверки предыдущих:

- разбиение формулы на независимые компоненты;
- memoization — запоминание уже решённых состояний;
- canonicalization — приведение состояний к каноническому виду;
- XOR и Gaussian elimination;
- сравнение с внешними SAT solvers;
- несколько точных представлений одной задачи;
- representation switching — переключение представлений;
- автоматический поиск семейств, где конкретный метод начинает расти экспоненциально.

## Главный принцип проекта

Нейросеть или эвристика в будущем может **предлагать**, что попробовать дальше, но она не должна определять математическую корректность ответа.

Правильность должна проверяться обычным кодом и, где возможно, формальными сертификатами.
