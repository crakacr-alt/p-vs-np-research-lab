# Безопасность проекта

P vs NP Research Lab — исследовательский инструмент. В обычном режиме он работает
локально и не требует сетевого доступа.

## MCP

MCP-интеграция предназначена прежде всего для локального `stdio`-подключения
к доверенному AI-клиенту.

В текущем релизе:

- нет инструмента для запуска произвольных shell-команд;
- нет инструмента для чтения произвольных файлов системы;
- файловые операции ограничиваются каталогом `PNP_LAB_WORKSPACE`;
- попытка выйти за пределы workspace через `../` отклоняется;
- MCP-инструменты публикуют только научные операции лаборатории.

Рекомендуется явно задавать:

```bash
export PNP_LAB_WORKSPACE=/полный/путь/к/p-vs-np-research-lab
```

## Данные экспериментов

Не помещайте в DIMACS-файлы, заметки гипотез или результаты экспериментов:

- пароли;
- API keys;
- токены;
- персональные данные;
- секретные корпоративные данные.

AI-модель может получить содержимое тех файлов, которые вы явно даёте ей через
инструменты лаборатории.

## Зависимости

Основной SAT core не имеет обязательных сторонних runtime-зависимостей.

Optional зависимости:

- `mcp>=2,<3` — только MCP-интеграция;
- `python-sat` — независимый reference solver;
- `ruff` — проверка кода.

Перед обновлением major-версии зависимости нужно прогонять CI и проверять
изменения API.

## Научная безопасность результатов

Отдельный риск — не компьютерная атака, а неправильный научный вывод.

Поэтому:

- SAT-модель перепроверяется отдельной функцией;
- малые задачи можно сверять с brute-force oracle;
- доступен independent PySAT reference;
- эксперимент не получает статус математического доказательства автоматически;
- в журнале гипотез намеренно нет автоматического статуса `PROVED`.

## Сообщение об ошибке

Если найдена ошибка, способная давать неверный SAT/UNSAT ответ, её нужно считать
критической для научной корректности проекта. В отчёте полезно приложить:

1. минимальный DIMACS-пример;
2. ожидаемый ответ;
3. фактический ответ;
4. команду запуска;
5. commit SHA;
6. версию Python.
